# Atlas Paper Trader — نسخهٔ آزمایشی برای Android + GitHub Actions

**معاملات ۱۰۰٪ مجازی هستند. هیچ API Key، رمز عبور یا سفارش واقعی به صرافی لازم نیست.**

## ساختار پروژه

- `src/strategy.py` — محاسبه Atlas V2 ALL + HARSI مطابق کد پژوهشی قبلی.
- `src/market.py` — API عمومی Binance Futures؛ اگر از ابتدا در دسترس نبود، Bybit Linear. پس از انتخاب منبع، بی‌صدا عوض نمی‌شود.
- `src/engine.py` — حساب مجازی مشترک، ثبت Long/Short، SL، Trailing و نصف خروج با HARSI + تأیید قیمت.
- `src/site.py` و `site/` — داشبورد موبایل؛ **هیچ معامله‌ای در مرورگر اجرا نمی‌شود**.
- `tests/test_engine.py` — تست‌های بدون اینترنت و با داده ساختگی؛ فقط برای کنترل درستی کد، نه ادعای سودآوری.
- `.github/workflows/paper-trader.yml` — اجرای برنامه در محیط GitHub، مستقل از موبایل.
- `data/state.json` — بعد از اولین اجرای اصلی ایجاد می‌شود و از طریق commit در مخزن باقی می‌ماند.

## راه‌اندازی مرحله به مرحله

1. یک مخزن **Public** با نام دلخواه مثل `atlas-paper-trader` در GitHub بسازید (شاخهٔ پیش‌فرض `main`). وضعیت معاملات مجازی و رویدادها عمومی خواهند بود؛ اینجا اطلاعات شخصی ذخیره نکنید.
2. فایل ZIP پروژه را **در بیرون GitHub استخراج کنید** و **محتویات داخل آن** را با همان ساختار پوشه‌ای در ریشهٔ مخزن قرار دهید. خود ZIP را تنها به مخزن آپلود نکنید، چون GitHub Actions آن را استخراج نمی‌کند.
3. در `Settings → Pages`، گزینهٔ `Source = GitHub Actions` را **پیش از اولین اجرای workflow** فعال کنید.
4. از تب `Actions`، workflow به نام **Atlas Paper Trader** را باز کنید، `Run workflow` را بزنید و حالت **`smoke`** را اجرا کنید. این اجرا بدون اینترنت همه تست‌ها را انجام می‌دهد. اگر سبز نشد، حالت `run` را شروع نکنید.
5. این اجرای نخست، تست آفلاین و بررسی ساختار فایل را انجام می‌دهد؛ در حالت `smoke` هیچ دادهٔ بازار یا معامله‌ای ثبت نمی‌شود.
6. دوباره `Actions → Atlas Paper Trader → Run workflow` را باز کنید و حالت **`run`** را انتخاب کنید. این اجرا دادهٔ واقعی را فقط از API عمومی دریافت می‌کند و حساب مجازی را راه‌اندازی می‌کند؛ به‌دلیل سیاست محافظه‌کارانه، در اولین اجرا وارد معاملهٔ قدیمی نمی‌شود.
7. لینک داشبورد پس از Deploy Pages در قسمت `Settings → Pages` یا خروجی کار `deploy` دیده می‌شود. در Chrome اندروید باز کنید و از منوی سه‌نقطه `Add to Home screen` را بزنید.
8. از این پس GitHub Actions طبق cron حدود هر ۱۵ دقیقه اجرا را **درخواست** می‌کند. اگر خطا یا تأخیر رخ دهد، داشبورد قرمز یا هشدار می‌شود. برای فهمیدن خطا به `Actions → آخرین اجرا` بروید.

اگر آپلود همزمان همهٔ پوشه‌ها در موبایل دشوار بود، یک **مخزن خالی** بسازید و لینک آن را در گفتگو بفرستید تا روش ساده‌تر انتقال فایل‌ها را مشخص کنیم. **توکن، پسورد، کلید API یا کد ورود GitHub را برای هیچ‌کس نفرستید.**

## قانون واقعی معاملات مجازی

- دادهٔ ۱ ساعته برای شکست سقف/کف ۲۴ کندل قبلی. فیلتر 4H EMA200 و شیب آن، ADX14 ≥22، شکست ≥ 0.25 ATR14 و ATR/close ≥ 0.4%.
- ورود مجازی فقط بعد از بسته‌شدن کندل با دادهٔ زمان واقعی آخرین قیمت و حداکثر تأخیر ۳۵ دقیقه؛ ورودهای از دست‌رفته با قیمت خیالی گذشته بازسازی نمی‌شوند.
- توقف اولیه ۲× ATR14، trailing با ۳× ATR14؛ ۰.۵٪ هدف ریسک از ارزش حساب، سقف مجموع حجم اسمی ۲ برابر سرمایه.
- HARSI بر اساس اندیکاتور JayRogers، Len=14 و smoothing=1: پس از رسیدن Close به 1R، دو کندل HARSI مخالف هشدار می‌دهند. اگر طی ۴ کندل بعدی قیمت کف/سقف ۶ کندل قبلی را بشکند، نصف موقعیت با قیمت جاری شبیه‌سازی می‌شود.
- کارمزد فرضی هر سمت ۰.۰۵٪ و لغزش هر سمت ۰.۰۲٪. این‌ها می‌توانند با شرایط واقعی فرق داشته باشند.
- SL با کندل‌های **۱ دقیقه‌ای** بین بررسی‌ها شبیه‌سازی می‌شود، نه با سفارش واقعی در دفتر سفارش. ترتیب نوسانات داخل یک دقیقه و شکاف‌های بازار می‌تواند نتیجه را متفاوت کند.
- Funding، liquidation دقیق، spread و هزینهٔ اجرای سفارش واقعی مدل نشده‌اند. **خرید و فروش واقعی انجام نمی‌شود.**

## محدودیت‌های مهم

- GitHub Actions **سرویس ۲۴/۷ بدون توقف نیست**. ممکن است اجرای cron به تأخیر بیفتد، حذف شود یا در مخزن عمومیِ بدون فعالیت ۶۰ روزه غیرفعال شود.
- اگر دادهٔ API در دسترس نباشد، حالت ERROR نمایش داده می‌شود و معامله‌ای جعل نمی‌شود.
- اگر اطلاعات بازار پیوسته نباشد، موتور محافظه‌کارانه عمل می‌کند و وضعیت را هشدار می‌دهد. مخصوصاً پس از وقفه بیش از ~۱۶ ساعت نمی‌توان SL واقعی را از روی داده‌های محدود دقیقه‌ای مطمئن بازسازی کرد.
- عملیات اصلی در سرورهای رایگان GitHub اجرا می‌شود و کارکرد آن به بازبودن صفحهٔ موبایل وابسته نیست؛ اما **زمان‌بندی و اجرای دقیق تضمین نمی‌شود**. این پروژه فقط برای پژوهش و Paper Trading است، نه مدیریت معاملات واقعی.
- وضعیت حساب در GitHub عمومی ذخیره می‌شود. از توکن صرافی، کلید خصوصی یا اطلاعات مالی واقعی استفاده نکنید.

## اجرای تست‌ها روی کامپیوتر یا محیط Python

```bash
python -m unittest discover -s tests -v
python main.py smoke
```

نسخهٔ اول، یک **ابزار آزمایشی** است. برای اتصال واقعیِ زنده، باید مرحلهٔ `run` در GitHub با موفقیت بازار را دریافت کند و منبع داده در داشبورد دیده شود. سبزبودن تست آفلاین به معنی بررسی دسترسی API از GitHub نیست.
